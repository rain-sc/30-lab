# 開獎動畫方案

開獎時的攪珠動畫已確定方案。前端負責動畫，**後端不需要等動畫**，只要提供下面「後端需要配合」的資料。

原型：[prototypes/draw-stage.html](prototypes/draw-stage.html)（直接用瀏覽器打開）

## 畫面

- 一個圓形玻璃球（扭蛋機造型），裡面有 **49 顆 3D 號碼球**，在重力作用下堆在底部（類似 Tsum Tsum）。
- **可下注時**：玩家可以點球（彈跳）、按住（放大看號碼）、拖動甩球。
- **截止後**：停止互動，球被「吹氣」攪動。
- **開獎時**：開出的號碼對應的**那顆球**從球堆彈出，飛到上方結果列，沿軌道滾到自己的位置，停下時號碼朝前。依序開出 6 個正碼 + 1 個特別號碼。

技術：three.js（3D 渲染）+ matter.js（2D 物理）；開獎過程由自訂的時間軸函數控制，一般 UI 動畫用 Motion。
實作在 `frontend/src/features/draw/stage/`（原型改寫成 TypeScript；用純 three.js，沒有用 React Three Fiber）。目前期數、號碼是前端示例資料，接上後端後換成 API 和 WebSocket 推送。

## 時間軸

```
04:45  CLOSED   攪珠開始（15 秒，不需要知道結果）
05:00  DRAWN    收到號碼 → 每 3.6 秒開出一顆，共 7 顆
~05:30          動畫結束，停在結果畫面，直到下一期 CLOSED
```

- 動畫進度由「**現在距離開獎時間過了多久**」計算出來，不依賴前端計時器。
  重新整理、切換分頁回來時，已開出的球直接擺好，正在開的那顆接著播。
- 用戶開啟「減少動態效果」（`prefers-reduced-motion`）時，不播動畫，直接顯示結果。
- 結算可能比動畫早完成。**中獎提示、積分變化由前端延後到動畫結束才顯示**，後端照常推送即可。

## 後端需要配合

| # | 需求 | 原因 |
|---|---|---|
| 1 | 期數資料包含 `closeAt`、`drawAt`（UTC ISO 字串） | 前端用來算倒數和動畫進度。`data-model.md` 的 `draws` 已有這兩個字段 |
| 2 | `numbers` **保留開出的順序**，不要排序；前端顯示時自己排序 | 動畫要按開出順序逐顆播放 |
| 3 | 期數相關的回應帶 `serverTime`（UTC ISO，毫秒精度） | 前端用來校正本機時鐘誤差。HTTP `Date` 標頭只到秒，不夠準 |
| 4 | 有一個「取得目前期數」的接口，`DRAWN` 之後的回應包含 `numbers`、`specialNumber` | 重新整理或晚進頁面時，直接拿到結果 |
| 5 | WebSocket 在期數狀態變更時推送（至少 `CLOSED`、`DRAWN`），`DRAWN` 的訊息包含號碼和 `drawAt` | 準時開始攪珠和開球；推送晚到時前端會繼續攪珠等待 |

接口路徑、topic 名稱、欄位命名由後端設計 API 時決定，寫進 `api-changelog.md`。
