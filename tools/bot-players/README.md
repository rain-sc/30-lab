# 機器人玩家

模擬 50~100 個玩家自動簽到、下注，讓開獎、派彩、排行榜、冷熱號碼在沒有真實玩家時也有資料。
只打公開的 HTTP API（跟真人一樣：註冊 / 登入 → 簽到 → 下注），不直接讀寫資料庫。

## 執行

需要 Node 18 以上（用內建的 `fetch`），沒有任何套件要安裝。先啟動後端，再在**根目錄**執行：

```powershell
node tools/bot-players/bots.mjs                                   # 預設 80 個機器人，連 http://localhost:8088

$env:BOT_COUNT=20; node tools/bot-players/bots.mjs                # 少量試跑
$env:BASE_URL="http://localhost:8099"; node tools/bot-players/bots.mjs   # 連別的後端
```

`Ctrl + C` 停止：還沒送出的下注會全部取消，已經送出的照常開獎、派彩。

| 環境變數 | 預設 | 說明 |
|---|---|---|
| `BOT_COUNT` | `80` | 機器人數量（1~100） |
| `BASE_URL` | `http://localhost:8088` | 後端位址 |
| `BOT_PASSWORD` | `bot-password-2026` | 所有機器人共用的密碼 |
| `QUIET` | （不設） | 設成 `1` 時只顯示每期的開始和總結，不顯示每一筆下注 |

Log 範例：

```

11:25:52   阿明（bot_001・休閒・生日號碼）下注 7 注 −70 → 餘額 10,930
11:25:58   Lucky7（bot_003・大戶・幸運號碼）下注 26 注 −260 → 餘額 8,440
11:26:41   小胖（bot_011・大戶・隨機選號）下注 12 注 −120 → 餘額 0（想下 28 注，積分只夠 12 注）
11:27:10   老王（bot_008・常客・隨機選號）積分不足（剩 0），這期不下注
11:30:30 [20261022-0042] 下注完成：60 張注單、1,147 注、11,470 積分（2 個略過）
```

## 行為

- **帳號**：`bot_001` ~ `bot_100`，暱稱像真人（阿明、Lucky7、小美…），同一個編號永遠是同一個暱稱。第一次執行自動註冊，之後是登入
- **簽到**：啟動時、跨 UTC 日時，所有機器人各簽到一次（今天已經領過就略過）
- **下注**：每 2 秒查一次 `GET /api/draws/current`；新的一期開放時決定誰要下注，下注時間隨機分散在「開放後 3 秒 ~ 截止前 5 秒」
- **玩家類型**（依編號固定）：

  | 類型 | 比例 | 每期下注機率 | 每次注數 |
  |---|---|---|---|
  | 休閒 | 15% | 65% | 5~10 |
  | 常客 | 35% | 60% | 10~20 |
  | 大戶 | 50% | 80% | 20~30 |

  80 個機器人平均每期大約 55 張注單、1,100 注；要調整就改 `bots.mjs` 開頭的 `PERSONAS`
- **選號習慣**（依編號固定）：完全隨機、固定幸運號碼（每次留 3~4 個）、只選 1~31（生日號碼；球數少於 31 時就是全部號碼）。號碼範圍從 `GET /api/game/rules` 的 `maxNumber` 讀
- **積分不夠**：少下幾注或這期不下，等隔天簽到
- **被登出**（例如有人用機器人帳號登入）：自動重新登入一次

## 注意

- 機器人帳號會建立在後端連到的資料庫裡，會出現在排行榜上
- 要清掉機器人：刪除 `username` 以 `bot_` 開頭的使用者，以及他們的錢包、流水、注單（目前沒有提供腳本）
